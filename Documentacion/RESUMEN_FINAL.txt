💡 CONSIDERACIONES IMPORTANTES
═══════════════════════════════════════════════════════════════════════

⚠️  CRÍTICAS
   • Esta es una refactorización DESTRUCTIVA
   • Requiere migración de datos ANTES de eliminar tablas
   • Hacer BACKUP de BD y cache antes de cambios

⚡  PERFORMANCE
   • Cache en memoria es ~1000x más rápido que BD
   • JSON admite estructura flexible
   • Thread-safe con locks (RLock)

🔐  SEGURIDAD
   • Asegurar permisos en /cache/ (no acceso público)
   • Datos sensibles (pagos) siguen en BD encriptada
   • Implementar encriptación de archivos JSON si es crítico

🌐  PRODUCCIÓN (Multi-instancia)
   • Con múltiples servidores, sincronizar /cache/
   • Considerar: Redis + Base de datos compartida
   • O: NFS/shared filesystem para /cache/
